Visao Geral

O backend expõe uma API REST para uma aplicacao escolar. Ele gerencia alunos, professores, integrantes da diretoria, usuarios autenticaveis e perfis de acesso.

FrameworkASP.NET Core 10 Web API.
PersistenciaEntity Framework Core com SQL Server e SQLite para desenvolvimento/testes.
SegurancaJWT Bearer, roles e hash de senha PBKDF2-SHA256.
DocumentacaoSwagger/OpenAPI com suporte a Bearer Token.
ValidacaoFluentValidation registrado no pipeline MVC.
ObservabilidadeLogs diarios em Backend_API/logs.

Tipo de Arquitetura

O projeto usa arquitetura em camadas. A camada HTTP conversa com services, os services executam regras de aplicacao e delegam persistencia ao repository ou ao DataContext. ViewModels isolam contratos externos das entidades EF Core.

API

Controllers, middlewares, autenticacao, autorizacao, Swagger e respostas HTTP.

Aplicacao

Services com regras de negocio, orquestracao e retorno de ViewModels.

Infraestrutura

Repository, DataContext, migrations, hashing, logging e acesso ao banco.

Dominio/Dados

Models, relacionamentos EF Core, seeds e constraints.

Diagrama de Fluxo da Requisicao

Cliente / SPA-> HTTP-> JWT-> Roles-> Controller-> Validator-> Service-> Repository-> EF Core-> SQL Server

O retorno percorre o caminho inverso: banco, EF Core, repository, service, ViewModel, controller e resposta HTTP. O middleware de logs registra inicio, fim, status e tempo de execucao.

Regras de Negocio

  • Todo endpoint de negocio exige JWT valido.
  • Administrador possui acesso total a CRUDs, usuarios e perfis.
  • Contribuinte cria e atualiza alunos, professores e diretoria, mas nao exclui.
  • Leitor consulta endpoints autenticados de leitura.
  • Usuarios novos recebem senha padrao Senha@252525.
  • Ao usar a senha padrao, a aplicacao sinaliza troca obrigatoria antes de liberar o fluxo normal.
  • Senha e armazenada apenas como hash PBKDF2-SHA256.
  • Aluno precisa de professor valido.
  • Aluno, professor e diretoria podem ou nao ter usuario vinculado.
  • Data de nascimento deve estar no formato dd/MM/yyyy.

Autenticacao e Autorizacao

O endpoint POST /api/Auth/login valida email e senha, gera JWT com claims de usuario e perfil, e retorna a flag deveAlterarSenhaPadrao.

ClaimOrigemUso
sub/nameidentifierIdUsuarioIdentifica usuario atual.
emailEmailIdentificacao e auditoria.

A API aplica migrations automaticamente no startup. Para SQLite em desenvolvimento, usa EnsureCreated.

FluentValidation

Validators sao registrados no pipeline MVC. Eles impedem payloads invalidos antes que os services executem regras de aplicacao.

  • AlunoCreateEditViewModelValidator: nome, sobrenome, data, professor e usuario.
  • ProfessorCreateEditViewModelValidator: nome e usuario vinculado.
  • DiretoriaCreateEditViewModelValidator: nome e usuario vinculado.
  • UsuarioCreateViewModelValidator: nome, email, telefone e perfil.
  • LoginRequestViewModelValidator: email e senha.
  • AlterarSenhaViewModelValidator: senha atual, nova senha forte e confirmacao.

Logging

O projeto possui provider proprio de log em arquivo: DailyFileLoggerProvider. Ele grava arquivos diarios na pasta Backend_API/logs.

OrigemEvento registrado
StartupAmbiente, diretorio de logs e preparacao do banco.
MiddlewareMetodo, rota, usuario, status HTTP e tempo de execucao.
ControllersExcecoes capturadas em CRUDs e autenticacao.
AuthControllerLogin recusado, login aceito e alteracao de senha.

O arquivo Backend_API/logs/.gitkeep versiona a pasta. Logs reais sao ignorados pelo Git.

Swagger/OpenAPI

Swagger e configurado em Program.cs com comentarios XML, titulo, versao, descricao e esquema de seguranca Bearer.

Fluxo recomendado: executar POST /api/Auth/login, copiar o token, clicar em Authorize e informar Bearer {token}.

Testes Unitarios

Os testes ficam em Backend_API/form_API.Tests e usam xUnit, Moq, FluentValidation.TestHelper e SQLite em memoria.

  • Controllers: validam respostas principais de Aluno e Usuario.
  • Services: validam criacao, hash de senha, login e troca de senha.
  • Validators: validam regras de entrada.
  • Seguranca: teste impede uso de APIs de SQL bruto.

Comando: dotnet test form_API.Tests/form_API.Tests.csproj.
